## 四、应急处理流程

### 4.1 P0-紧急问题处理流程

```
发现问题
  ↓
确认问题级别（P0/P1/P2/P3）
  ↓
[P0-紧急] 立即处理 + 在用户群/邮箱发公告
  ↓
排查根因（查日志、查数据库、查代码）
  ↓
实施修复（回滚版本 / 修数据 / 热修复）
  ↓
验证修复（测试核心功能）
  ↓
发布事后复盘报告（3天内）
```

### 4.2 常见问题应急预案

#### 问题1：网站完全无法访问
**排查步骤**：
1. 访问 Vercel Dashboard 查看部署状态
2. 检查 DNS 解析（ping zhiyingxuehai.com）
3. 检查 Supabase 状态（status.supabase.com）

**修复方案**：
- 如 Vercel 部署失败 → 回滚到上一个成功版本
- 如 DNS 问题 → 联系域名服务商
- 如 Supabase 宕机 → 启动备用方案

#### 问题2：数据库查询慢/超时
**排查步骤**：
1. 登录 Supabase Dashboard → Database → Query Performance
2. 查看慢查询日志
3. 检查是否缺少索引（运行 `supabase/fix-missing-indexes.sql`）

**修复方案**：
- 添加缺失索引
- 优化慢查询 SQL
- 增加数据库连接池大小（如需）

#### 问题3：用户无法登录
**排查步骤**：
1. 检查 Supabase Auth 状态
2. 查看用户反馈的错误信息
3. 测试登录流程（用测试账号）

**修复方案**：
- 如 Supabase Auth 故障 → 等待恢复或联系 Supabase 支持
- 如代码 bug → 热修复并重新部署
